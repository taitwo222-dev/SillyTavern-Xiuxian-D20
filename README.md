# 修仙 D20 一键安装器（SillyTavern）

用于在 SillyTavern 中安装一套修仙题材 D20 判定系统。

当前版本：**1.1.7**。修正归零问题的调查记录：[证据、历史提交与修复范围](docs/modifier-regression.md)。

本项目只提供 D20 系统本身，不包含、复制、修改或冒用任何第三方预设原版。

## 自动安装内容

- 4 条 Regex：
  - `D20_提取ACTION`
  - `D20_提取DC`
  - `D20_提取MOD`
  - `D20_提取DETAIL`
- 1 套 `修仙D20` Quick Replies（7 个 QR）
- 2 套 D20 裁判规则：
  - `修仙D20·核心裁判系统`
  - `修仙D20·每轮强制检查`
- 天道点自动奖励运行时：负责识别已正式成立的里程碑、去重、+1 与上限控制。

这两套规则由扩展直接注入，不会自动复制当前预设，也不会生成“某某预设 + D20”之类名称。

## 安装

在 SillyTavern：

1. 打开 Extensions / 扩展。
2. 选择 Install Extension / 安装扩展。
3. 粘贴：

```text
https://github.com/taitwo222-dev/SillyTavern-Xiuxian-D20.git
```

4. 安装后刷新 SillyTavern。
5. 建议点击一次 `🎲D20初始化`。

已有用户更新到 1.1.7 后刷新页面即可；扩展会迁移自身配置，不需重新初始化聊天。初始化按钮会清空天道点及当前判定缓存，只在确实想重置时使用。现有待结算骰点会继续保持原先锁定的条件。

## 天道点获取机制

天道点上限为 **5**。除了保留的手动 `☯ 天道+1` 按钮外，1.1.6 起新增三类自动奖励：

- USER **正式完成一次新的境界/小境界突破**：`+1`。
- USER **完成一个新的秘境**：`+1`。
- USER **首次征服一名新的女修**：`+1`；同一名女修只奖励一次。

自动奖励只在事件已经成为正式世界事实后触发。仍处于 D20 待结算、尚未收到 `[D20_ACCEPT]` 的突破或其他事件不会提前奖励。

模型会输出隐藏的 `[D20_TIANDAO_AWARD]` 机器标记；扩展负责：

- 固定每个合格里程碑只加 1 点；
- 依据类型与稳定 KEY 去重；
- 天道点最多加到 5；
- 满 5 时仍记录该里程碑为已处理，防止之后重复刷取；
- 从可见正文中自动移除机器标记。

去重规则：突破按新达到的境界/小境界标识，秘境按秘境名称/唯一标识，女修按 NPC 稳定姓名/唯一标识。关系加深、重复确认、再次进入同一秘境或重复叙述同一次突破都不会再次奖励。

扩展内部提供 `/xiuxian-d20-tiandao-reset` 用于清空自动奖励记录与天道点，主要供完整重置同一聊天时使用。

## DC量表与硬校验

基础DC只描述行动本身的客观难度，优先使用：5（极易）、8（很容易）、10（常规）、12（有一定难度）、15（困难）、18（很困难）、20（极难）、22（顶尖难度）、25（近乎极限）、30（仍然可行但近乎极限）。

- 正式 D20_REQUEST 的 DC 必须在 **5—30**。
- 一般应落在 **5—25**；DC 30 仅用于特殊极限情况。
- 如果合理难度必须超过 30，则当前条件下不应投骰，应先改变客观条件或直接判定无法完成。
- 扩展会在投骰前硬校验 DC；例如 `DC=75` 会直接拒绝，不会再进入骰点流程。
- 同一事实不能既提高 DC，又在 DETAIL 中再次作为负修正重复计算。
## 修正明细校验

自动处理器先从最新 AI 原始消息中读取完整 `D20_REQUEST`，核对 ACTION、DC、MOD 与 DETAIL，再允许 Quick Reply 投骰。`DETAIL` 可以跨行，但每项要写成 `具体因素(+整数)` 或 `具体因素(-整数)`。

- `DETAIL=控火熟练(+2)，神识疲惫(-2)` 对应 `MOD=0`，合法。
- 确实没有有效修正时，写 `DETAIL=无直接相关修正(0)：当前场景的具体原因`，对应 `MOD=0`。
- 缺字段、总和不符、重复因素或没有说明的全零清单会暂停投骰，提示在投骰前核对；扩展不会猜测角色加值。
- 点击 `测试DETAIL` 可检查原始请求、合计与当前缓存。检查不会重投或修改已经锁定的判定。

扩展不读取或改写用户预设本体，规则补全与请求校验都在本扩展内完成。自动测试运行：`npm test`（Node.js 20+，不需安装第三方依赖）。

## 两套 D20 规则模板

### 修仙D20·核心裁判系统

文件：`assets/prompts/d20-core.txt`

负责：判定适用范围、DC/MOD 锁定、结果等级、成功奖励、失败后果、突破/炼丹/炼器/破禁制/神识等修仙能力检定。

### 修仙D20·每轮强制检查

文件：`assets/prompts/d20-guard.txt`

负责：每轮先检查是否需要 D20、待结算冻结、结果接受/重Roll流程、天道点自动里程碑检查，以及与其他状态系统的兼容。

## 关于预设

本项目没有任何第三方预设原版。

因此：

- 不会把当前预设复制成“原预设名 + 修仙D20”。
- 不会在名称里带其他模板、角色卡或预设的名字。
- 不会删除用户酒馆里已经存在的其他预设。
- 本项目自身的 D20 规则内容只保留上面两套模板。

如果想手动粘贴，请查看：`manual/预设手动粘贴版_README.md`。
