# v1.1.5 修正归零调查

调查基线：`c1ada2120491f34e5340670f6fb4ae2fe81e15b8`（manifest 1.1.4）。对照了仓库全部 41 次提交、原始手动 QR/Regex、用户提供的旧版 D20 规则与当前两段规则。没有提交或修改第三方预设文件。

## 先区分生成、提取与计算

原链路：模型根据规则生成 ACTION/DC/MOD/DETAIL → `{{lastCharMessage}}` → 四次 `/regex` → 写入聊天变量 → 外部 D20 → RAW + MOD → 临时结果注入 → 重Roll或接受。

旧版和 1.1.4 的 Quick Reply 都没有评估角色能力、给技能定数值的代码。DETAIL 是模型生成的文字，Regex 只截取，重Roll只替换 RAW。因而不能用“骰子把加减项都算成了 0”解释所有现象。

已有截图中，DETAIL 的两项本身为 `+0`，而 ACTION 为空；这是“请求生成或提取后已经是全零”的证据，不能仅凭截图区分取到了草稿、旧缓存，还是模型正式请求就写了全零。没有那两轮原始消息、最终发送给模型的提示及当时启用集合，不能诚实地宣称某一次提交已被证明是这两次输出的唯一原因。

当前两段规则没有“所有修正都设为0”的指令，且仍要求全部加减项合计等于 MOD。禁止重复计算不意味着可以不评估角色的实际优势和劣势。全零是否符合某场景，需要角色、技能、装备与当时状态作依据，扩展不会凭空判给正数或负数。

## 本次修复

1. 自动 QR 在外部投骰前调用 `/xiuxian-d20-prepare`。直接读取当前 AI 消息，跳过思考块内的草稿；只接受一个完整正式请求。字段缺失、重复、非整数、明细合计不符时，返回 false，既不投骰也不把无效数据转换为0。
2. 有正负项相抵的净0照常有效；确实无修正可写 `无直接相关修正(0)：具体原因`。全零占位清单要求核对，不自动生成新的加减值。跨行明细与常见全角数值可解析。
3. 恢复旧版丢失的数据约定。既有能力与状态是投骰前评估输入；冻结行动结果不等于停止读取已有条件。
4. 清理器按实际 UI 块边界删除留言和选项，保护 D20 请求及此前状态；不再从前一个 details 跨到后面的留言。
5. 安装器共享真实版本，在配置保存成功后才更新版本记录。旧名集合的 D20 按钮迁移到当前逻辑、重复自动处理器停止自动执行；自定义按钮保留。
6. `测试DETAIL` 显示原始请求、合计、当前缓存、消息位置与校验错误。待结算期间不重算已锁定条件；升级不重置骰点或天道点。

独立手动包仍可不安装扩展运行，因此保留 STscript/Regex 路径，只同步请求边界提取；它没有 JavaScript 校验器的完整保证，见手动说明。
